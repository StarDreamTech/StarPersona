# WorkBuddy 代理与 Camoufox 实测

日期：2026-11-18。本机 Apple Silicon macOS，Camoufox `159.0-beta.42`，StarPersona 的真实 Rust `BrowserManager`。

**结论：这批代理可以接入现有 SOCKS5 配置；本次未发现 WebRTC 公网地址泄漏，断代理后未回退直连。但节点存在出口重复、出口变化，以及对个别检测站点的访问异常，不能把 40 个端口当作 40 个固定独立 IP。**

## 测试来源与范围

- 只读加载 WorkBuddy 代理池配置 中的 40 个已启用节点；均为本机 `socks5h://127.0.0.1:<port>`，没有代理认证。
- 实际由 本机 mihomo 进程提供 40 个 SOCKS 监听，各自指向 Trojan 上游。浏览器连接的是本机 SOCKS 端口，不需要直接支持 Trojan。
- 使用临时工作空间、40 个独立浏览器 profile、直连及失效代理控制组；每批最多 4 个浏览器。没有导入或修改用户的生产工作空间。
- 先用 curl 测 HTTP/HTTPS，再用真实管理器启动 Camoufox 测网页请求和 STUN；额外以普通有界面窗口检查 DNS 交接、WebRTC、断开及恢复。
- 测试只向 ipify、example.com、Cloudflare STUN 发起网络请求，没有登录账号、调用 WorkBuddy 模型接口或消费模型额度。出口 IP 仅在内存比较，证据文件保存 SHA-256。

## 对环境隔离的影响

1. 多个代理端口可以共用公网出口。按表中 E 组选择不同出口，并在每次启动环境时重新检查，不应只根据代理名称或端口区分。
2. 多次样本中，同一端口可能返回不同出口；P01 的三次独立 HTTPS 重试已经出现 2 个出口。原因尚未定位到上游节点或链路，当前不能承诺固定 IP。HTTP 与 HTTPS 出口不同也应单独提示。
3. P09、P10 对 ipify 多次失败，但对 example.com 的 HTTP/HTTPS 都返回 200。因此应标记“检测站访问异常”，不能仅据此判定代理彻底离线。
4. P21、P22 的检测出口与本机基线相同。仅凭 IP 相同不能证明请求绕过了代理；需结合上游路由、运营方出口与连接记录定位。
5. 代理不会修复上一轮 Canvas 重启变化或系统与 GPU 不一致的问题；完整设备指纹验收仍未通过。

## DNS 与 WebRTC 的边界

DNS 探针使用临时本机 TCP 中继记录 SOCKS5 握手，然后转发到 P01；真实浏览器向 ipify 和随机 `qa-*.example.com` 发出 ATYP=3 域名请求。域名探针本身预期不能获得正常页面，它用于检查解析交接。没有抓取系统全部 DNS/DoH 流量，也没有控制权威 DNS 的查询日志；没有验证 mihomo 及 Trojan 上游最终在哪个地区解析，不能宣称“DNS 完全不泄漏”。

WebRTC 使用 Cloudflare STUN、每次最多 6 秒；40 个代理样本均只有 mDNS 类型的 host 候选，未采到公网 srflx 候选，直连控制组则能采到。普通窗口额外复核一致。mDNS 是遮蔽本机地址的主机名，不等于 WebRTC 经过了该 SOCKS 代理，也不能推导所有通话功能正常。

本机直连基线表示浏览器/命令未配置应用代理，不保证计算机或网络不存在系统路由、VPN 或其他透明转发。没有独立验证公网 IPv6、多地区 GeoIP、住宅 IP、DNS 地区匹配、实际业务站点或风控通过率。

## 复现

```sh
STARPERSONA_PROXY_POOL=/absolute/path/to/proxy-pool.json \
STARPERSONA_PROXY_EVIDENCE=/absolute/path/to/evidence.json \
cargo test --release --manifest-path src-tauri/Cargo.toml real_proxy_pool_collects_browser_evidence -- --ignored --nocapture
```

该集成采样入口仅接受无认证 SOCKS5 / socks5h 节点。`proxy-probe.html` 对空 ICE 事件作过滤，并断言候选类型有效，避免把“采集结束”空事件误记为公网地址。

证据：`proxy-browser-proof.json`、`proxy-transport-proof.json`、`proxy-retries.json`、`proxy-secondary-target.json`、`proxy-dns-outage-proof.json`、`proxy-runtime-sanitized.json`、`proxy-summary.json`。其中脚本的本机项目路径需要按复现机器调整。
