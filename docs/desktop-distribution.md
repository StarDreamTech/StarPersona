# 桌面版 0.2：内核、共享书签、环境编号和安装

## 创建窗口

打开「创建窗口 → 账号与启动」。平台和账号备注是本机别名，不是登录凭据。可选择保存时查重、禁止同账号同时打开，二者彼此独立。判定依据是 **平台 + 账号备注**，忽略前后空白和大小写；任一环境启用保护即参与校验。回收站环境不占名额，恢复时重新检查。复制环境不沿用账号备注或账号限制。不要在备注或启动链接里填密码、2FA 或访问令牌。管理器不会自动登录网站。

启动网址每行一个，最多 8 个 HTTP(S) 链接，留空显示星相启动页。Apple Silicon + Camoufox 159 实测：两个启动网址都产生了真实 HTTP 请求；开启账号独占后，再打开同平台同别名的第二个环境被拒。对照用的其他账号不受影响。规则覆盖桌面、CLI、MCP，不能控制用户自行在星相之外启动的浏览器。

## Camoufox 版本

在「配置内核 → Camoufox 官方版本」选版本，点「下载并校验」或「选用」，然后保存。星相复用官方预编译包，不再打开官方 GUI。大小来自 [Camoufox 的官方发布资产](https://github.com/daijro/camoufox/releases)，区分芯片与完整构建号；没有官方校验值或文件不匹配则不会安装。刷新失败仍可用内置版本表。每版本只存一份；切换的是全局内核，先关闭星相管理的窗口。用旧版做兼容性验证时请新建环境，不要拿日常资料降级。

## 书签和 Dock

- 左侧「共享书签」可统一添加、编辑、删除。启用「环境间同步」并重开环境后，新建的普通网页书签在其他环境的书签工具栏「星相共享书签」出现。约每 3 秒同步一次，需星相运行；离线环境在下次连接时追上。不开启会保留私人书签。首次启用前已有的书签不会批量上传，书签文件夹层级、排序、Cookie、历史、密码不共享。冲突不静默覆盖较新的中心记录。
- 真实双环境检查：A 新增 → B 收到；在中心改名和删除 → A、B 均更新。测试使用临时资料，没有读取用户的私人书签。
- macOS 可在「配置内核」勾选 Dock 编号，重新打开环境后生效。编号来自环境序号，不更改网站标签或网页 favicon。实机 Dock 看到了测试环境 **71、72**。系统可能同时保留普通 Camoufox 图标，因此默认关闭。未验收多显示器及所有 macOS 版本的切窗行为。

## Apple Silicon Homebrew 分发

维护者运行 `./scripts/package-homebrew.sh`。输出 `.artifacts/homebrew/` 下的 ZIP、`SHA256SUMS` 和固定摘要的 `starpersona.rb`。打包本身不会创建 GitHub Release 或更改组织 tap。发布时把 ZIP 放到同一源码版本的 GitHub Release `v<version>`，把对应 Cask 放进 `StarDreamTech/homebrew-tap/Casks/`。不要复用旧版本号替换已发布的二进制。

**在 Release 和 Cask 都上线后**，使用：

```sh
brew install --cask stardreamtech/tap/starpersona
```

以后可关闭星相管理的浏览器，点「系统设置 → 通过 Homebrew 检查并更新」，更新后退出并重新打开星相。也可以使用：

```sh
brew update && brew upgrade --cask stardreamtech/tap/starpersona
```

手工解压的 `.app` 不会自动转为 Homebrew 管理。现有 `/Applications/StarPersona.app` 如果不是 Homebrew 安装，请先备份，不要用强制覆盖命令。当前构建只做本机临时签名，未做 Apple Developer ID 签名或公证。本机检查了压缩包 SHA-256、解包后签名、版本和 Cask 的 Ruby 语法；Homebrew 7 因临时 tap 未获信任，在加载 Cask 前停止，未验证由线上版本升级，也未改动信任设置。
